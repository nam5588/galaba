# PRD: 학교 공지사항

- 문서 상태: MVP 구현 기준
- 작성일: 2026-10-03
- 제품: UniMate (유학생 행정비서)
- 담당 영역: 학교 공지 탐색 및 상세 확인

## 1. 배경과 문제

외국인 유학생은 학사, 장학, 국제처, 시설 공지가 여러 채널에 흩어져 있어 중요한 기한과 행정 절차를 놓치기 쉽다. 한국어 제목만으로 중요도를 판단하기 어렵고, 필요한 공지를 다시 찾는 데도 시간이 든다.

UniMate의 학교 공지사항 기능은 주요 공지를 한 화면에 모으고, 검색·분류·중요도 표시·상세 확인을 제공해 사용자가 필요한 정보를 빠르게 찾도록 돕는다.

## 2. 목표

1. 사용자가 최신 학교 공지를 한곳에서 확인할 수 있다.
2. 제목, 요약, 내용, 담당 부서를 기준으로 공지를 검색할 수 있다.
3. 학사·장학·행정·공모행사 카테고리로 결과를 좁힐 수 있다.
4. 중요한 공지를 일반 공지와 시각적으로 구분한다.
5. 목록을 벗어나지 않고 공지 상세 내용을 확인할 수 있다.
6. 홈 화면과 통합 검색에서 공지 화면으로 자연스럽게 이동할 수 있다.

## 3. 비목표

MVP에서는 다음 항목을 구현 범위에 포함하지 않는다.

- 대학 홈페이지 실시간 크롤링 또는 공식 시스템 연동
- 관리자용 공지 작성·수정·삭제
- 로그인 사용자별 읽음 상태 및 북마크 영구 저장
- 자동 번역, 알림 발송, 캘린더 등록
- 첨부파일 다운로드 및 외부 원문 링크

## 4. 주요 사용자

- 한국 대학에 재학 중인 외국인 유학생
- 비자·장학·수강·교내 시설 관련 공지를 정기적으로 확인해야 하는 학생
- 긴 한국어 공지에서 핵심 내용과 담당 부서를 빠르게 찾고 싶은 학생

## 5. 핵심 사용자 시나리오

### 시나리오 A: 최신 중요 공지 확인

1. 사용자가 홈 화면의 학교 공지사항 카드 또는 왼쪽 메뉴를 선택한다.
2. 최신순 공지 목록이 표시된다.
3. 중요 공지는 `중요` 배지로 구분된다.
4. 사용자가 공지를 선택하면 같은 화면에서 상세 내용과 담당 부서가 펼쳐진다.

### 시나리오 B: 공지 검색

1. 사용자가 공지 화면 검색창에 키워드를 입력한다.
2. 입력 후 250ms 동안 추가 입력이 없으면 검색 요청을 보낸다.
3. 제목, 요약, 본문, 담당 부서에 키워드가 포함된 결과만 표시한다.
4. 결과가 없으면 안내와 필터 초기화 동작을 제공한다.

### 시나리오 C: 카테고리 필터

1. 사용자가 전체·학사·장학·행정·공모행사 중 하나를 선택한다.
2. 선택한 카테고리와 검색어를 동시에 적용한다.
3. 선택된 필터를 시각적으로 명확하게 표시한다.

## 6. 기능 요구사항

| ID | 요구사항 | 우선순위 |
|---|---|---|
| NOTICE-01 | 공지를 최신 등록순으로 표시한다. | Must |
| NOTICE-02 | 공지 카드에 카테고리, 중요도, 제목, 요약, 담당 부서, 등록일을 표시한다. | Must |
| NOTICE-03 | 검색어를 제목·본문 요약·담당 부서에 적용한다. | Must |
| NOTICE-04 | 전체·학사·장학·행정·공모행사 필터를 제공한다. | Must |
| NOTICE-05 | 공지를 선택하면 상세 본문을 펼치거나 접을 수 있다. | Must |
| NOTICE-06 | 로딩, 빈 결과, API 오류 상태를 각각 제공한다. | Must |
| NOTICE-07 | 오류 발생 시 다시 시도할 수 있다. | Must |
| NOTICE-08 | `/notices?search=<검색어>` 진입 시 검색어를 적용한다. | Must |
| NOTICE-09 | `/notices#notice-<id>` 진입 시 해당 공지를 펼치고 화면에 위치시킨다. | Should |
| NOTICE-10 | 데스크톱과 모바일 화면에서 검색·필터·상세 확인이 가능해야 한다. | Must |

## 7. 화면 및 상호작용 요구사항

- 왼쪽 공통 내비게이션에서 `학교 공지사항`을 현재 메뉴로 표시한다.
- 상단에는 기능 제목, 설명, 공지 아이콘을 표시한다.
- 검색창과 카테고리 필터는 하나의 필터 패널에 배치한다.
- 공지 목록은 아코디언 형태로 동작하며 한 번에 하나의 상세 공지를 연다.
- 중요 공지는 일반 공지와 다른 배지와 강조색을 사용한다.
- 로딩 중에는 레이아웃 이동을 줄이기 위한 스켈레톤을 표시한다.
- 모바일에서는 배지, 제목, 상세 본문이 좁은 너비에서도 읽히도록 재배치한다.

## 8. 데이터 및 API 계약

### 요청

`GET /api/notices`

선택 쿼리:

- `category`: `학사 | 장학 | 행정 | 공모행사`
- `limit`: 1~20

검색은 받아온 공지의 제목, 요약, 담당 부서에 클라이언트에서 적용한다.

### 응답

```ts
interface NoticesResponse {
  source: 'live' | 'cache' | 'sample'
  fetchedAt: string
  items: Notice[]
}

interface Notice {
  id: number
  category: string
  tag: string
  tone: 'red' | 'blue' | 'green'
  title: string
  date: string
  text: string
  url: string
  dept: string
  pinned: boolean
}
```

지원하지 않는 카테고리는 서버에서 `전체`로 처리한다.

## 9. 오류 및 예외 처리

- API 연결 실패: 오류 메시지와 `다시 시도` 버튼을 표시한다.
- 검색 결과 없음: `검색 결과가 없어요` 메시지와 `필터 초기화` 버튼을 표시한다.
- 빈 검색어: 전체 공지를 조회한다.
- 지원하지 않는 카테고리: 클라이언트에서는 선택할 수 없으며 API는 전체 공지로 대체한다.
- 빠른 연속 입력: 250ms 디바운스로 불필요한 요청을 줄인다.

## 10. 성공 지표

- 공지 화면 진입 후 첫 결과 표시 성공률 99% 이상
- 검색 또는 카테고리 선택 후 결과 표시 시간 1초 이내(로컬 API 기준)
- 중요 공지 상세 열람률
- 빈 결과 후 필터 초기화 성공률
- 모바일 환경에서 기능 완료율이 데스크톱 대비 유의미하게 낮지 않을 것
